# Registro de decisões (ADR resumido)

| #   | Decisão                                                                                                          | Motivo                                                                                                                                                  | Alternativas                                             |
| --- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1   | Pacote extra `packages/orchestrator`                                                                             | API e worker precisam da mesma lógica de domínio com I/O; `agents` fica puro (sem banco) e testável.                                                    | Duplicar lógica na API/worker.                           |
| 2   | Uma sessão por agente; trava por `UPDATE … WHERE active_run_id IS NULL`                                          | Garante histórico independente e impede execuções simultâneas na mesma sessão sem depender de lock distribuído. Locks > 10 min são considerados órfãos. | Redlock/Redis lock.                                      |
| 3   | Mensagem de chat guardada no `agent_run.input` até o turno começar                                               | Evita intercalar a mensagem do usuário com um turno de tarefa em andamento (histórico consistente e sem "prefill").                                     | Gravar imediatamente.                                    |
| 4   | Continuidade de contexto por reenvio do histórico próprio (últimas 40 mensagens)                                 | Funciona igual em Anthropic e OpenAI via API; não depende de conversas das interfaces web.                                                              | Estado de conversa no servidor do provedor.              |
| 5   | Eventos persistidos com `bigserial` + Redis pub/sub + replay por `Last-Event-ID`                                 | Reconexão robusta, ordenação total por projeto, múltiplas réplicas da API.                                                                              | WebSocket; Redis Streams.                                |
| 6   | Deltas de streaming transitórios                                                                                 | Evita inflar o banco; a mensagem final é persistida.                                                                                                    | Persistir cada delta.                                    |
| 7   | Modo demo decidido pelo **projeto**                                                                              | Impede que um projeto demo faça chamadas pagas por engano e rotula tudo como demo.                                                                      | Por agente.                                              |
| 8   | Preços: só os publicados (Anthropic, cache 2026-10-06); OpenAI configurável pelo usuário                         | Requisito de não inventar preços; custo desconhecido aparece como `null`.                                                                               | Tabela estimada.                                         |
| 9   | IDs de modelos: sugestões Anthropic reais + lista ao vivo via Models API; OpenAI só pela API                     | Requisito de não inventar identificadores.                                                                                                              | Lista fixa.                                              |
| 10  | Chaves de API com AES-256-GCM (`ENCRYPTION_KEY`) e nunca retornadas                                              | Segredo só no backend; UI recebe apenas uma dica.                                                                                                       | KMS (recomendado em produção — ver SECURITY).            |
| 11  | Proxy same-origin `/api/*` no Next                                                                               | Cookies first-party (httpOnly, SameSite=Lax), sem CORS no navegador, SSE funciona via rewrite.                                                          | API em outro domínio com CORS.                           |
| 12  | Arte do escritório procedural em PixiJS                                                                          | Original, leve, sem licenças de terceiros, estado visual 100% derivado de dados.                                                                        | Sprite sheets raster.                                    |
| 13  | shadcn/ui escrito à mão sobre `radix-ui`                                                                         | O CLI do shadcn depende de registry externo; os componentes seguem o mesmo padrão.                                                                      | CLI.                                                     |
| 14  | Chat Completions na OpenAI                                                                                       | API estável com streaming + `include_usage` + tool calls no SDK v7.                                                                                     | Responses API (pode ser adicionada como novo adaptador). |
| 15  | Ferramentas de agente limitadas a ler artefatos do projeto                                                       | Sem shell/rede/execução de código; resultados marcados como não confiáveis.                                                                             | —                                                        |
| 16  | Plano sempre exige aprovação humana; entrega final também                                                        | Requisito de supervisão humana e de limites de autonomia.                                                                                               | Execução automática.                                     |
| 17  | TypeScript 5.9 (não 7.x)                                                                                         | Compatibilidade com typescript-eslint e Next 16 no momento da implementação.                                                                            | TS 7 (nativo).                                           |
| 18  | Groq, OpenRouter e Ollama via o mesmo `OpenAIAdapter` (API compatível com OpenAI) com predefinições por provedor | Um único código cobre os três; diferenças tratadas no adaptador (`max_tokens`, uso em `x_groq`, repetição sem ferramentas se o modelo não suportar).    | Um adaptador por provedor.                               |
| 19  | Limites por provedor (concorrência, tokens de saída, orçamento de histórico) e espera maior em 429               | Planos gratuitos têm cotas pequenas por minuto; reservar a vaga antes de gravar estado evita execuções órfãs.                                           | Deixar o provedor recusar.                               |
| 20  | URL personalizada só para Ollama e só com `ALLOW_CUSTOM_PROVIDER_URLS`                                           | Evita SSRF: Groq/OpenRouter têm endereço fixo.                                                                                                          | URL livre para todos.                                    |
| 21  | Custo US$ 0 para Ollama e para contas marcadas como plano gratuito                                               | Pedido do usuário de operar sem custo, sem inventar preços para planos pagos.                                                                           | Custo "desconhecido".                                    |
